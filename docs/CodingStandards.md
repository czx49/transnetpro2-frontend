# C/C++ 编码规范

## 1. 文件编码

- 所有代码文件使用 UTF-8 无 BOM（代码页 65001），换行符使用 CRLF。
- C++ 程序入口在 Windows 环境下应设置控制台输出为 UTF-8 编码。

## 2. 命名规范

- 代码命名以驼峰法为基础，命名应清晰且尽量简洁。
- 文件名、文件夹名使用全小写，必要时可使用下划线 `_` 强调或分隔，避免不同系统对大小写敏感度差异带来的问题。
- C++ 源文件使用 `.cpp` 后缀，头文件使用 `.h` 后缀。
- 变量、函数形参使用小驼峰（lowerCamelCase）。
- 全局变量增加 `g_` 前缀。
- 类成员变量使用小驼峰，并增加 `m` 前缀；`m` 后不加下划线。
- 类成员函数使用小驼峰。
- 类名使用大驼峰（UpperCamelCase）。
- 结构体、联合体、枚举名使用大驼峰。
- 非类成员函数可使用大驼峰，以强调其独立性。
- 宏定义使用全大写，单词之间用下划线连接。
- 枚举值使用大驼峰。

## 3. 注释规范

### 3.1 文件注释

文件头部按需添加 Doxygen 注释，内容可包含说明、版本号、生成日期、作者、功能、修改历史等。作者不强调时默认填写 `zhangmg`。

```cpp
/*****************************************************************//**
 * \file   文件名
 * \brief  文件简介
 * \details 文件的详细描述
 *
 * \author 作者
 * \date   February 2025
 * \History 修改的历史纪录
 *********************************************************************/
```

### 3.2 类注释

类头部应添加 Doxygen 注释，说明类的简介、功能、作者和日期。作者不强调时默认填写 `zhangmg`。

```cpp
/**
 * \brief  类简介
 * \details 类的详细介绍
 * \author 作者
 * \date   类的生成日期
 */
```

### 3.3 函数注释

函数应添加 Doxygen 注释，说明函数功能、参数、返回值、作者和日期。作者不强调时默认填写 `zhangmg`。

```cpp
/**
 * \brief  函数简介
 * \details 函数的详细介绍，包括使用说明和功能作用
 * \param  参数名，和参数作用及使用
 * \return 返回值的说明，包括可能的值及含义
 * \author 函数作者
 * \date   函数开发日期
 */
```

也可使用简易版本；函数简介与详情之间保留一个空行。

```cpp
/**
 * 函数简介
 *
 * 函数的详细介绍，包括使用说明和功能作用
 * \param  参数名，和参数作用及使用
 * \return 返回值的说明，包括可能的值及含义
 * \author 函数作者
 * \date   函数开发日期
 */
```

### 3.4 变量注释

为便于 Doxygen 输出，变量注释采用以下形式之一：

- 在变量上方使用 `///` 或 `//!` 注释。
- 在变量右侧使用 `///<` 或 `//!<` 注释。

### 3.5 TODO 注释

临时写法或因业务不确定性可能调整的代码，应添加 `TODO` 注释并说明原因。

```cpp
// TODO do something
```

### 3.6 代码注释

单行注释中，注释符与注释内容之间至少保留 1 个空格。

## 4. 头文件规范

- 所有头文件使用 `#ifndef`/`#define`/`#endif` 防止多重包含，保护符应唯一，命名可基于头文件名。
- 除文件头注释外，不要在包含保护区域前后放置代码或注释。
- 头文件只放置模块或单元对外接口，包括对外函数声明、宏定义、类型定义等。
- 内部使用的宏、枚举、结构定义不应放入头文件。
- 禁止头文件循环依赖，例如 `a.h` 包含 `b.h`，`b.h` 包含 `c.h`，`c.h` 再包含 `a.h`。
- 禁止包含未使用的头文件。
- 禁止在头文件中定义变量，避免被多个 `.cpp` 文件包含后产生重复定义。
- 头文件包含顺序建议为：项目内头文件、第三方库头文件、C++ 标准库头文件。按稳定度排序，不稳定的头文件放在前面。

```cpp
/****************************
 * \file filedialog.h
 **************************/
#ifndef FILE_DIALOG_H
#define FILE_DIALOG_H

#endif
```

```cpp
#include "product.h"
#include "platform.h"
#include <QObject>
#include <memory>
```

## 5. 格式规范

### 5.1 行宽

- 每行不超过 120 个字符，超过时应合理换行。
- 包含 URL 的行可保持一行。
- 部分预处理命令可保持一行。

### 5.2 缩进

- 使用空格缩进，每级缩进 4 个空格。
- 禁止使用 Tab 缩进。

### 5.3 大括号

- 程序块左大括号 `{` 和右大括号 `}` 独占一行，并位于同一列。
- 空函数体可将大括号放在同一行。
- `if`、循环等语句即使只有一条语句，也必须使用大括号。

### 5.4 函数参数

- 函数声明过长时应换行，形参可对齐，也可在下一行缩进 4 个空格。
- 函数调用入参的换行方式应与形参换行风格保持一致。
- 对无需修改且拷贝成本较高的参数，优先使用常量引用，避免不必要的拷贝。

### 5.5 变量定义与赋值

- 不允许在同一行定义或赋值多个变量。

### 5.6 空格

- `if`、`switch`、`case`、`do`、`while`、`for` 等关键字后加空格。
- 一元运算符（如 `&`、`*`、`~`、`!`）后不加空格。
- 二元运算符（如 `=`、`+`、`-`、`<`、`<=`、`>`、`>=`、`!=`、`%`）左右两侧加空格。
- 三目运算符 `? :` 两侧加空格。
- 逗号前不加空格，逗号后加空格。
- 成员操作符 `.`、`->` 前后不加空格。
- 域操作符 `::` 前后不加空格。
- 模板和类型转换中的 `<>` 不加空格。

### 5.7 空行

- 不使用连续三个空行，保持代码紧凑。

### 5.8 类访问修饰符

- 类成员声明顺序为 `public`、`protected`、`private`。
- 访问修饰符缩进与 `class` 关键字对齐。

### 5.9 const

- 不修改成员变量的成员函数应使用 `const` 修饰。
- 指针或引用类型的函数形参，应根据只读属性使用 `const` 修饰。

## 6. 作用域规范

### 6.1 命名空间

- 命名空间建议不超过 2 层。
- `.cpp` 文件中不需要导出的变量、常量、函数或类，应使用匿名命名空间封装，或使用 `static` 修饰；现代 C++ 推荐优先使用匿名命名空间。
- 未做内部链接限制的符号默认具有外部链接（external linkage），链接器会认为这些符号可被其他编译单元使用，可能导致多个定义冲突。
- 不要在头文件中或 `#include` 之前使用 `using` 导入命名空间，避免影响后续代码并造成符号冲突。

### 6.2 函数返回值

- 禁止返回函数内临时变量的引用或地址。
- 尽量避免直接以类类型作为函数返回值；如果返回值是可持久化的左值，可使用引用返回。
- 新建对象建议使用智能指针返回。
- 带返回值的函数必须确保所有路径都有返回值。

## 7. 其它规范

- 不要保存 `std::string::c_str()` 返回的指针；标准不保证该指针长期有效，应在需要时调用。
- 重写父类虚函数必须添加 `override`，以便编译器检查重写是否正确。
- 可能被继承的类，其析构函数必须声明为 `virtual`，避免通过基类指针释放对象时子类析构函数不被调用。
